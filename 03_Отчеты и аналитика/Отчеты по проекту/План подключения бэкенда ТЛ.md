# План подключения бэкенда для централизации данных портала ТЛ

**Дата:** 26.10.2026
**Статус:** подключение выполнено (26.10.2026): tl-firebase.js + правки ядра + SDK в портале/курсах; добавлены firestore.rules. Осталось: применить правила в консоли Firebase и протестировать.

## Проблема

Портал и курсы работают офлайн-прототипом: все данные (пользователи, сессии, прогресс) хранятся в `localStorage` браузера каждого пользователя. При тестировании VR-курса на GitHub Pages регистрации учеников видны только в их собственных браузерах — у педагога/админа их нет.

**Причина:** GitHub Pages — статический хостинг, без сервера и БД. Синхронизации между браузерами нет.

## Цель

Централизованное хранение: регистрация, вход и прогресс пишутся в удалённую БД; педагог/админ видят всех учеников и их достижения из любого браузера.

---

## Варианты реализации

### Вариант A. Firebase (рекомендуется для быстрого старта)
- **Плюсы:** бесплатный тариф (Spark) достаточен, мгновенная настройка, реальное время (Realtime Database), работает со статикой GitHub Pages (без своего сервера).
- **Минусы:** требуется аккаунт Google, внешний сервис (для учебного объединения ок).
- **Состав:** Firebase Auth (вход/регистрация) + Firestore/Realtime DB (профили, прогресс).

### Вариант B. Supabase (open-source, Postgres)
- **Плюсы:** SQL-БД, бесплатный тариф, Row Level Security, удобная админка.
- **Минусы:** чуть больше настройки, требует API-ключи.

### Вариант C. Свой лёгкий сервер (Express/Node + JSON-файл или SQLite)
- **Плюсы:** полный контроль, данные в своей организации.
- **Минусы:** нужен хостинг с серверным кодом (не GitHub Pages), обслуживание, цена.

**Рекомендация:** **Вариант A (Firebase)** — быстрее всего даёт результат при минимальной инфраструктуре.

## Что нужно изменить в коде (объём работ)

### 1. Ядро `tl-portal-core.js` (мастер + 8 копий курсов)
- Заменить локальные `register` / `login` / `logout` на **Firebase Auth + Firestore**:
  - `register()` → `auth.createUserWithEmailAndPassword` + запись профиля в `users/{email}`.
  - `login()` → `auth.signInWithEmailAndPassword`, сессия — через Firebase (не `tl.session`).
  - `logout()` → `auth.signOut()`.
- **Совместимость:** хранить профиль в том же формате (`id, role, name, cls, school, phone, email, labs, passHash`, но пароль — в Auth, не хэшем в БД). Старые локальные данные (если есть) — при первом входе мигрировать.
- **Офлайн-режим:** оставить падение на localStorage, если Firebase недоступен (graceful degradation).

### 2. Прогресс занятий (все курсы + VR)
- Ключи прогресса: `tl.progress.<courseId>` (ядро), `{prefix}{uid}_l_{N}` (lesson_l), `pdn-course-progress-{uid}` / `bpla-…` и т.д. (week_obj, idField).
- Синхронизировать **запись** прогресса на сервер: `progress/{courseId}/{uid}/{lesson}`.
- При открытии курса — **читать прогресс с сервера** в localStorage (или напрямую).

### 3. Профили курсов (VR: `vr_profiles`, `vr_current_user`; другие — свои ключи)
- `tl-bridge.js` каждого курса: вместо локального `courseProfiles()`/`saveCourseProfiles()` — читать/писать в `course-profiles/{courseId}` на сервере.
- `syncFromUrl()` (автосоздание профиля по `?tl_email=`) — тоже писать на сервер.

### 4. Педагог/админ (уже есть UI)
- `getStudentsForTeacher()` / `getUsers()` / «Пользователи» / «Заявки» — перевести на чтение **из сервера** (Firestore), а не из localStorage.
- «Экспорт всех»/«Импорт всех» (JSON) остаются как резервный канал.

### 5. Конфигурация
- Новый файл `firebase-init.js` (или блок в ядре) с `firebaseConfig` (ключи проекта) + подключение SDK (npm/cdn).
- Переменные окружения/ключи — **не в git** (пример в `.env.example`, реальные — в настройках деплоя или в локальном файле, исключённом из репозитория).

## Порядок внедрения (мильник)

1. **Этап 0. Подготовка**
   - Создать проект Firebase (например, `tehnolab-portal`).
   - Включить Auth (email/password), Firestore (правила: читать свой прогресс + админ/педагог видят своих учеников).
2. **Этап 1. Подключение SDK к порталу**
   - Добавить `firebase-config.js` + инициализацию в `tl-portal-core.js`.
   - Правка `register/login/logout` → Firebase Auth.
   - **Проверка:** регистрация/вход на портале работают через Firebase, сессия живая.
3. **Этап 2. Синхронизация прогресса**
   - В ядрах курсов и мосту — запись/чтение прогресса в Firestore.
   - **Проверка:** прохождение занятия видно у педагога.
4. **Этап 3. Админка/педагог**
   - Перевод чтения учеников/заявок на Firestore.
   - Порядок прав доступа (security rules): ученик — только свои данные, педагог — свои группы, админ — всё.
5. **Этап 4. Тест и публикация**
   - Тест на GitHub Pages с двух браузеров (ученик + педагог).
   - Миграция старых локальных данных (по желанию).
   - Обновить README/инструкцию.

## Риски и ограничения
- **Безопасность:** Firebase security rules нужно настроить корректно (не открывать коллекции на чтение всем).
- **Совместимость:** ВАЖНО — все копии `tl-portal-core.js` (8 курсов) должны обновляться синхронно, чтобы ключи не разъехались.
- **Офлайн:** GitHub Pages остаётся, но при недоступности сети Firebase — локальный режим.
- **Стоимость:** Spark-тариф бесплатен (до ~50k чтений/день); для школы — с запасом.
