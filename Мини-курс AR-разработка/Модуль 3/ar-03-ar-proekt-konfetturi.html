03·AТеория по шагам

1

Меню выбора

В углу экрана — горизонтальное меню с предметами (стул, стол, лампа). Нажатие выбирает, какой размещать.

Меню — это «витрина» твоего приложения: оно показывает пользователю, что можно поставить, и переключает режим размещения. За кулисами каждая кнопка просто меняет одну переменную — какой префаб сейчас будет создаваться по касанию. Это очень удобный дизайн: ты не пишешь отдельный код под каждый предмет, а держишь массив предметов и указываешь его индекс при нажатии кнопки. Один скрипт обслуживает всё меню.

Жизненная аналогия

Вспомни раздаточный автомат или кафе с сенсорным заказом. Ты нажимаешь «пиццу» или «сок» — автомат думает: «сейчас буду готовить именно это». Так же и AR-меню: нажал «стул» — телефон «берёт» из своей кладовки префаб стула и готов ставить его по твоему касанию.

В мебельных приложениях вроде IKEA Place точно такое же меню: сетка предметов внизу экрана, выбираешь диван — и дальше расставляешь по комнате. Такой простой принцип «меню задаёт выбор» лежит в основе большинства AR-игр и приложений.

Запомни. Меню = список предметов; выбор задаёт, что размещаем. Один массив префабов + индекс кнопки = сколько угодно предметов.
2

Размещение и перемещение

Кнопка «Разместить» ставит предмет по касанию. Перетаскивание (drag) — перемещает уже размещённый предмет.

Тут два разных действия, и важно их не путать. «Разместить» создаёт новый объект — сначала его нет, после касания он появляется. «Переместить» не создаёт ничего нового, а берёт уже стоящий объект и двигает его по плоскости. Технически перемещение делается «физическим» касанием: луч ищет collider уже размещённого предмета, «цепляет» его и перетаскивает за пальцем. Размещение же ищет не объект, а свободную плоскость.

Разместить vs Переместить
ДействиеЧто ищет лучРезультат
РазместитьРаспознанную плоскостьНовый объект создан
ПереместитьCollider стоящего объектаОбъект переехал на новое место
Пример
// Идея сценария: два луча
// 1) Попал в collider объекта на сцене — берём его для перетаскивания
// 2) Иначе ищем плоскость — размещаем новый предмет
if (Physics.Raycast(ray, out var hit) && hit.collider) {
    grabbed = hit.collider.gameObject;          // цепляем средний предмет
} else {
    TryPlaceNew();                               // или ставим новый
}

В приложении для покупок мебели это незаменимо: поставил диван к одной стене, передумал — «перетащил» к другой. Не создавая лишний предмет, а просто двигая уже существующий. Так интерфейс остаётся чистым и не захламляется.

Запомни. Разместить — по касанию; перетащить — переместить существующий. У размещённого объекта должен быть Collider, чтобы его можно было «схватить».
3

Удаление

Кнопка «Удалить» убирает последний размещённый предмет или предмет, на который навёл.

Чтобы «удалить» работало аккуратно, приложение ведёт список размещённых объектов — обычно массив в памяти: каждый новый предмет добавляется в конец. Кнопка «Убрать последний» просто уничтожает последний элемент из списка. Важно и то, что предмет действительно уничтожается: если просто «спрятать» его, он останется в памяти и замедлит приложение. Поэтому удаление — это ещё и забота о производительности, особенно когда объектов много.

Пример · список размещённых объектов
List<GameObject> placed = new List<GameObject>();

void PlaceAt(Pose pose, GameObject prefab) {
    var obj = Instantiate(prefab, pose.position, pose.rotation);
    placed.Add(obj);                  // добавляем в список
}

public void DeleteLast() {
    if (placed.Count == 0) return;    // нечего удалять
    Destroy(placed[placed.Count - 1]);
    placed.RemoveAt(placed.Count - 1);
}

Так же устроены «корзины» в AR-приложениях для интерьера: можно поставить десять предметов, посмотреть, как они смотрятся вместе, а потом убрать лишние по одному. Список размещённых объектов — базовая «память» твоего приложения.

Запомни. Управление коллекцией размещённых объектов. Веди список (List), чтобы знать, что удалять; удаление через Destroy освобождает ресурсы.
4

Сборка

Собери всё вместе и запусти на устройстве. Проверь на разных поверхностях и освещении.

Почему так важно тестировать в разных условиях? AR — хрупкая технология: она живёт реального мира. Волнительное освещение, блестящий пол или быстрые движения рук — и картинка «плывёт», а объекты начинают дрожать. Слабый свет мешает камере находить «особые точки» для плоскости; слишком яркое солнце даёт блики; а глянцевые поверхности почти не отдают деталей алгоритму. Готовый проект проверяют в трёх-четырёх ситуациях, чтобы не отдать пользователю приложение, которое работает только в одном углу класса.

Чек-лист тестирования
УсловиеНа что смотреть
Хороший свет, матовый полОбъект стоит ровно, плоскость ловится быстро
Приглушённый светПлоскость может искаться дольше — норм
Глянцевая поверхностьРаспознавание слабее — предупреди пользователя

Вспомни популярные AR-приложения: они всегда подсказывают «наведи камеру на ровную поверхность с хорошим светом». Теперь ты понимаешь, почему — это не прихоть, а условие, при котором алгоритму проще и точнее строить мир.

Запомни. Готовая AR-демо «примерка мебели» в реальной комнате. Тестируй на разных поверхностях и освещении — AR зависит от условий камеры.
