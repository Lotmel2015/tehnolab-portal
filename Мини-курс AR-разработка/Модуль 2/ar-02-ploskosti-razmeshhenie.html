02·AТеория по шагам

1

Raycast

По касанию экрана пускается «луч»; если он попадает в распознанную плоскость — получаем точку, куда ставить объект.

Почему именно «луч», а не просто координата? Экран — это двумерная картинка, а мир вокруг — трёхмерный. По одному касанию телефон не знает, на каком расстоянии от него находится поверхность. Поэтому от камеры в направлении твоего пальца физически «выстреливается» луч, и движок ищет, во что он врежется. Первое пересечение луча с распознанной плоскостью и даёт точку в 3D-пространстве — там и появляется объект. Это как смотреть через трубочку на пол: она указывает направление, а точка приземления на полу — место цели.

Как работает Raycast
ШагЧто происходит
1Ты касаешься экрана — телефон читает координаты пальца.
2От камеры пускается луч в этом направлении.
3Луч пересекает плоскость → получена точка установки.
4Объект появляется ровно в этой точке.
Пример
ARRaycastManager.Placement.cs
var hits = new List<ARRaycastHit>();
if (rayManager.Raycast(touch.position, hits, TrackableType.PlaneWithinPolygon)) {
    var pose = hits[0].pose;              // точка пересечения луча с плоскостью
    Instantiate(objPrefab, pose.position, pose.rotation);
}

Тот же принцип использует IKEA Place: ты наводишь телефон на пол, касаешься — и шкаф «встаёт» ровно там, где коснулся. За кулисами камеры тоже летит луч и находит точку на распознанной плоскости пола.

Запомни. Raycast: коснулся → луч → точка на плоскости → точка установки. Луч нужен, чтобы перевести 2D-касание в 3D-координату.
2

Режим размещения

Обычно на экране кнопка «Разместить». Пока касание активное — объект «летит» за пальцем, при отпускании закрепляется.

Это режим «предпросмотра»: ещё до установки ты видишь, как объект будет стоять, и можешь выбрать точное место. Именно поэтому в хороших AR-приложениях объект держат полупрозрачным или с лёгкой подсветкой, пока он «летит» за пальцем — так пользователю ясно, что предмет ещё не закреплён. Как только отпускаешь, объект становится обычным и остаётся на плоскости. Такой приём делает приложение понятным и бережёт пользователя от ошибки «поставил не туда».

Жизненная аналогия

Представь, что ты раскладываешь игрушечные машинки на ковре. Пока рука держит машинку, ты двигаешь её в нужное место. Отпустил — машинка осталась там, где лежит. В AR «рука» — это твой палец, а луч — направление, по которому ты «кладёшь» объект на плоскость.

В реальной жизни этот режим ты точно видел в приложениях для примерки мебели: ведёшь телефон по комнате, диван «подъезжает» к стене, выбираешь удобное место — отпустил палец — и диван «встал». Разработчик просто не даёт ставить объект в воздух: пока не наведён на плоскость, кнопка не активна.

Запомни. Размещение по касанию: объект двигается, пока палец на экране. Обычный признак готовности — объект «прилип» к плоскости.
3

Якоря

Якорь (Anchor) — точка, к которой прикреплён объект. Так модель «приклеивается» к реальному месту и не «уплывает» при движении камеры.

Почему без якоря объект «уплывает»? Рисунок AR собирается из картинки камеры и догадок алгоритма о мире. Когда ты двигаешь телефон, алгоритм вынужден заново угадывать, где что находится, и допускает небольшие ошибки. Якорь — это «закладка», которую система хранит в памяти: закреплённая точка надёжно привязана к деталям реальной поверхности. Пока эти детали видны, объект будет стоять строго на своём месте, даже если камера слегка ошиблась.

С якорем и без
СитуацияБез якоряС якорем AR Anchor
Неподвижный телефонОбъект стоитОбъект стоит
Водишь камеройОбъект дрожит и «плывёт»Объект стоит стабильно

Поэтому в мебельных AR-приложениях каждый размещённый шкаф или диван получает свой якорь. Отойди подальше, вернись — шкаф всё ещё стоит на том же месте в комнате, а не «перепрыгнул». Так создаётся ощущение, будто предмет — часть реального мира, а не просто картинка поверх экрана.

Запомни. ARAnchor фиксирует объект в точке реального мира. Якорь помогает объекту не «плыть», когда ты двигаешь камеру.
4

Практикум

Собери сцену: кнопка «+» размещает куб по касанию; второй куб — уже автоматически на первую найденную плоскость.

Здесь ты впервые увидишь два разных способа размещения. Первый — по касанию: пользователь сам выбирает место, это гибко и удобно. Второй — автоматический: как только найдена первая горизонтальная плоскость, движок сам ставит объект в её центр. Это хороший стартовый приём для простых демо — не нужно тыкать в экран, объект появляется сам. В серьёзных приложениях часто используют оба: авторазмещение для «первого» объекта и касание для всех остальных.

Сравнение способов
СпособКак работаетКогда подходит
По касаниюПользователь выбирает точкуМного объектов, точная расстановка
АвторазмещениеОбъект встаёт в первую плоскостьБыстрый старт, демо
Пример · авторазмещение на первую плоскость
// слушаем событие появления плоскости
void OnPlaneAdded(ARPlaneAddedEventArgs evt) {
    var plane = evt.plane;
    if (firstSpawned) return;                 // ставим только первый раз
    firstSpawned = true;
    Instantiate(cubePrefab, plane.center, Quaternion.identity);
}

Придумай соревнование сам: кто из одноклассников быстрее расставит пять кубов по касанию по краям стола? Теперь у тебя есть для этого инструмент.

Запомни. Собери размещение по касанию + авторазмещение на первую плоскость. По касанию — гибко, авто — быстро.
