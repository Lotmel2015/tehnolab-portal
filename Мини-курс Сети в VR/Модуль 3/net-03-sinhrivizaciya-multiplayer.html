03·AТеория по шагам

1

Синхронизация позиции

Чтобы все видели движение объекта, его позицию и поворот передают по сети. Photon Transform View делает это автоматически.

Как это работает «под капотом»? Владелец объекта несколько раз в секунду отправляет пакет с координатами (позицией, поворотом, масштабом). Остальные принимают пакет и плавно «доезжают» до полученной точки — этот механизм называется интерполяцией (Interpolate). Без интерполяции объект стоял бы тихо, а потом резко прыгал бы на новое место — заметная «дёрганость». Поэтому в Photon Transform View обычно включают Interpolate (плавность) и Set to Targets (на какую точку стремиться). В VR синхронизация позиции особенно требовательна: голова и руки игрока двигаются быстро, и маленькая задержка или дёрганье сразу ломают ощущение «я там» — поэтому в гарнитурах борются за минимальную задержку.

Пример
// Настройка на компоненте Photon Transform View:
// Synchronize Position   → Interpolate  (плавно догонять)
// Synchronize Rotation   → Interpolate  (плавно поворачиваться)
// Serialize Type         → All (передавать и позицию, и поворот)
Что ты увидишь
Когда один игрок двигает объект, у остальных он движется плавно, без прыжков.
РежимЧто делает
InterpolateПлавно «едет» к последней полученной позиции — нет прыжков
TeleportМгновенно переносит объект в новую точку — для редких перемещений
ManualПередаёшь координаты сам — полный контроль, но больше кода
Запомни. Photon Transform View = синхронизация позиции/поворота/масштаба. Включи Interpolate, чтобы движение было плавным. Пакеты шлют много раз в секунду.
2

Сетевые события (RPC)

Действия, которые должны увидеть все, вызываются как RPC (Remote Procedure Call) — «вызвать функцию на всех устройствах». Например, «поднять флаг» или «играть звук».

В чём разница между обычным вызовом и RPC? Обычный метод (например, PickupCoin()) выполняется только у того игрока, который его вызвал. RPC — это «приказ», который Photon рассылает всем устройствам в комнате, и у каждого выполняется одна и та же функция. Именно поэтому RPC идеален для редких событий: взял предмет, нажал кнопку, запустил звук, закончил раунд. Важно помнить два правила: у метода должен быть атрибут [PunRPC], а вызывать его нужно через photonView.RPC("ИмяМетода", RpcTarget.AllBuffered, ...) — иначе никто, кроме тебя, его не увидит. AllBuffered означает «разослать сразу всем, включая тех, кто войдёт позже» — так опоздавшие игроки не «пропустят» уже случившееся событие.

Код
using Photon.Pun;
public class Coin : MonoBehaviourPun {
    void OnTriggerEnter(Collider other){
        photonView.RPC("Pickup", RpcTarget.AllBuffered);
    }
    [PunRPC]
    void Pickup(){
        Destroy(gameObject); // выполнится у всех игроков разом
    }
}
Что ты увидишь
Монета исчезает одновременно у всех игроков — событие «рассылается» по комнате.
Запомни. RPC — метод, который выполняется у всех игроков одновременно. Атрибут [PunRPC] обязателен, вызывай через photonView.RPC. RpcTarget.AllBuffered — разослать всем, включая опоздавших.
3

Когда синхронизировать

Позицию движущегося объекта синхронизируют каждый кадр (Transform View). Редкие события (взял предмет, открыл дверь) — по RPC. Всё подряд слать нельзя — перегрузка сети.

Почему нельзя слать всё подряд? У сети есть лимит пропускной способности. Если каждый объект каждый кадр шлёт координаты + цвет + здоровье + открытую дверь, пакеты накапливаются, а конкуренция за канал растёт — игроки начинают «подвисать», а объекты «дёргаться». Поэтому инженеры делят данные на два потока: постоянные (движение, повороты — их передают часто и автоматически) и редкие «события» (одноразовые действия). Постоянное — через синхронизацию Transform View, редкое — через RPC. Правило «не перегружай сеть» — это про то, чтобы тратить байты только на нужное. В реальных играх используют и оптимизацию зон видимости: например, не передают движения объектов далеко от игрока.

Тип данныхКак передаватьПример
ПостоянноеЧасто, автоматически (Transform View)Движение персонажа, поворот головы
Редкое событиеОдин раз, по RPCВзял предмет, открыл дверь, сыграл звук
Редкие значенияСвойства Room/Player через OnPhotonSerializeViewГотовность игрока, выбранная роль
Запомни. Движение — каждый кадр, события — по RPC, не перегружай сеть. Дели данные на «постоянные» и «редкие», чтобы не тратить байты зря.
4

Сборка multiplayer-игры

Собери в одну сцену всё: меню, комнату, синхронизацию, RPC-события. Собери APK и запусти на двух гарнитурах.

Сборка — финальный «сборочный конвейер» проекта. Сначала проверь, что все префабы и сцены добавлены (сетевые префабы — в Resources, сцены — в Build Settings). Затем настрой платформу Android под гарнитуру и собери APK. После установки на два шлема помни: оба игрока должны использовать один и тот же App ID, иначе они не встретятся. Ещё один нюанс — порядок запуска: если оба шлема стартуют почти одновременно, оба найдут друг друга в комнате; если одного запустить сильно раньше, второй просто войдёт в уже созданную его напарником комнату. Так и работает честный multiplayer: кто первый создал комнату — тот стал хостом и «судьёй» этой сессии на своей гарнитуре.

Что ты увидишь
Два шлема, одна комната: игроки видят друг друга, объекты движутся плавно, счёт общий — настоящая multiplayer-игра работает.
Компонент финальной игрыЗа что отвечает
МенюИмя игрока, выбор/создание комнаты
Спавн игрокаPhotonNetwork.Instantiate — персонаж у всех
СинхронизацияPhoton Transform View — плавное движение
СобытияRPC — сбор монет, звуки, победа у всех
Запомни. Финальная сборка: меню → комната → совместная игра. Проверь App ID, префабы в Resources и сцены в Build Settings перед сборкой APK.
