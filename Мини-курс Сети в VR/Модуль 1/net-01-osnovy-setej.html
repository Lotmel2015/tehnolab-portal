01·AТеория по шагам

1

Клиент, сервер и хост

В сети все устройства называют клиентами. Один из них может быть сервером (владельцем мира). Хост — это «сервер + клиент» в одном: ты хостишь игру и сам в ней играешь.

Зачем вообще нужен «хозяин мира»? Представь, что три человека одновременно смотрят на один мяч: каждый пишет в групповой чат «мяч тут». Без общего «судьи» начался бы хаос — кто прав? Сервер (или хост) — это и есть такой судья: он решает, где на самом деле находится объект, и рассылает правду остальным. Поэтому сервер называют «авторитетным» (authoritative) игроком — его слово главное. В онлайн-играх это защищает и от читеров: взломанный клиент не сможет «приказать» миру, если сервер ему не верит.

РольЧто делаетПример в жизни
КлиентУстройство игрока: шлёт серверу, что ты нажал, и рисует то, что пришлоТы видишь картинку в шлеме и двигаешь руками
Сервер«Хозяин» мира: хранит правду о всех объектах и игрокахОбщий «мозг», который помнит, где кто стоит
ХостСервер + клиент одновременно: судит мир и сам в нём играет«Хозяин» комнаты в PUN: создал игру и сам в ней участвует

Простую аналогию: видеозвонок. Клиенты — участники, сервер — сервис, который соединяет всех и хранит конференцию. А пользователь, который создал конференцию «из своего устройства» (без отдельного сервера), — это хост. В Photon PUN 2 обычно работает именно хост-модель: тот, кто нажал «Создать комнату», становится хостом и его устройство заодно «судит» игру.

Запомни. Клиент — устройство игрока. Сервер — «хозяин» мира, его слово главное (это защищает от читеров). Хост — сервер, на котором тоже играют.
2

Сетевые объекты

Не каждый объект в Unity «виден» в сети. Чтобы объект был общим, он должен быть сетевым (PhotonView) и «спавниться» (создаваться) через сеть, а не через обычный Instantiate.

Почему обычный Instantiate не подходит? Когда ты делаешь Instantiate, Unity создаёт объект только у тебя — на других устройствах об этом никто не узнает. Чтобы объект появился у всех, нужно попросить Photon сделать это: PhotonNetwork.Instantiate отправляет запрос всем игрокам комнаты, и каждый создаёт одинаковый объект с одинаковым номером — ViewID. Именно по этому номеру устройства понимают: «ах, это тот самый общий куб, а не копия». Если в комнате двое, оба увидят один и тот же Prefab без «двойников».

Пример
using Photon.Pun;
public class SpawnExample : MonoBehaviourPun {
    void Start(){
        // так объект появится у всех в комнате:
        PhotonNetwork.Instantiate("MyCube", transform.position, Quaternion.identity);
    }
}
Что ты увидишь
Куб появился у каждого игрока, и у всех у него одинаковый ViewID — это один общий объект.
СпособГде появится объектКогда использовать
InstantiateТолько у тебяЛокальные эффекты, частицы, личные предметы
PhotonNetwork.InstantiateУ всех игроков комнатыПерсонажи, общие предметы, всё, что все должны видеть
Запомни. Instantiate создаёт объект у одного игрока. PhotonNetwork.Instantiate — у всех, и всем выдаётся одинаковый ViewID. Спавнишь только в папке Resources по имени префаба.
3

Владение объектом

У каждого сетевого объекта есть владелец — кто его создал. Владелец управляет объектом, остальные его видят. Это важно для физики и рук.

Владение (Ownership) решает главный вопрос: «у кого есть право менять объект?» Если бы менять объект могли все, то два игрока схватили бы один и тот же шар — и сервер не знал бы, чей приказ выполнять. Поэтому Photon позволяет менять объект только его владельцу: остальные просто «смотрят» и получают обновлённое положение. Внутри скрипта это проверяется через photonView.IsMine — если свойство true, ты владелец и можешь двигать объект; если false, это чужой объект, и его трогать нельзя.

Пример
using Photon.Pun;
public class NetPlayer : MonoBehaviourPun {
    void Update(){
        // двигаем объект только если он НАШ
        if (!photonView.IsMine) return;
        transform.Translate(Vector3.forward * 2f * Time.deltaTime);
    }
}
Что ты увидишь
Ты двигаешь только свой персонаж, а чужие персонажи других игроков стоят на местах — ведь они принадлежат другим.
КтоПрава над объектомphotonView.IsMine
ВладелецМожет управлять объектом (двигать, менять, удалять)true
ОстальныеТолько видят и получают обновления от владельцаfalse

В VR это особенно важно для рук: твои виртуальные руки — твоя собственность, и логика хватания проверяет, «моя ли это рука», прежде чем разрешить взятие предмета. Именно так устроено в реальных VR-играх про командную работу: каждый отвечает только за свои руки и предметы, а общим «миром» заведует хост.

Запомни. Кто создал объект — тот им владеет. Не путайте владельца и сервер. Проверка photonView.IsMine говорит, можно ли управлять этим объектом.
4

Photon и PUN

Photon PUN (Photon Unity Networking) — готовая библиотека многопользовательских игр. Unity Package Manager подключит пакет, а Photon даст бесплатный App ID.

Писать сеть «с нуля» — это писать протоколы, следить за потерянными пакетами и порядком сообщений: месяцы работы. PUN берёт всё это на себя: ты подключаешься к облаку Photon, получаешь App ID (свой «пароль» для доступа к серверам), и библиотека сама доставляет данные между игроками. При этом используется облачная схема Photon Cloud: у игры есть внешний сервер, а не только хост-устройство, поэтому игроки могут встретиться из разных городов и даже стран.

Код
using Photon.Pun;
public class NetPlayer : MonoBehaviourPun {
  void Start(){ if (photonView.IsMine) { /* этот игрок управляет собой */ } }
}
Что ты увидишь
На объекте виден компонент Photon View — значит, он сетевик.
ТерминЧто это
Photon CloudВнешние серверы Photon, которые соединяют игроков по всему миру
App IDУникальный «ключ» твоей игры — чтобы игроки твоей игры попадали в твои комнаты
PUNБиблиотека-«мост»: даёт PhotonView, комнаты, RPC и синхронизацию
Запомни. MonoBehaviourPun + photonView.IsMine — так проверяешь, твой ли это объект. App ID — общий «пароль», чтобы игроки встретились в одной комнате.

01·БПрактика

Выполняй по порядку. У каждого шага — что должно получиться.

1Установи Photon PUN 2 через Window → Package Manager → Add package (по имени com.unity.multiplayer... или скачай PUN с Asset Store)
Должно получиться: В проекте появился Photon, в папке Plugins/Photon.
2Получи бесплатный App ID на dashboard.photonengine.com (раздел Realtime) и впиши его в Photon Server Settings
Должно получиться: В Photon Server Settings зелёная галочка App ID.
3Создай сцену с землёй, добавь Cube с Photon View и компонент Photon Transform View
Должно получиться: Кубик — сетевой объект.
4Создай пустой объект с Photon View и в Start() вызовы PhotonNetwork.ConnectUsingSettings()
Должно получиться: В консоли — статус соединения (ConnectedToMaster).
5Подключись: сделай так, чтобы игрок мог зайти в «комнату» кнопкой
Должно получиться: Два запуска (Editor + сборка) попадают в одну комнату.

01·ВДомашнее задание

📋 Сделай сетевую сцену встречи двух игроков.

  1. Создай сцену с землёй и источником света.
  2. Для каждого игрока с помощью PhotonNetwork.Instantiate создай куб-персонаж.
  3. Управляй только своим кубом (photonView.IsMine).
  4. Проверь: два устройства видят друг друга и оба могут двигаться.
Что должно получиться: Сцена, где два игрока одновременно видят друг друга и двигают свои кубы.

01·ГМетодичка

Пошагово: действие → что появится

Шаг 1. Установи PUN 2

Открой Window → Asset Store (или Package Manager) и добавь Photon PUN 2 Free

✔ В проекте появляется папка Photon.
Шаг 2. Зарегистрируйся в Photon

Открой dashboard.photonengine.com, создай приложение Realtime, скопируй App ID

✔ В настройках Photon сервера App ID заполнен.
Шаг 3. Сделай первого сетевого персонажа

Добавь на куб Photon View + Photon Transform View, напиши скрипт NetPlayer

✔ Куб становится сетевым объектом с владельцем.
Шаг 4. Подключись и зайди в комнату

Создай код подключения и входа в комнату

✔ В консоли статус ConnectedToMaster и CreatedJoining Room.
Шаг 5. Проверь на двух устройствах

Запусти в Editor и на собранном APK

✔ Оба игрока в одной комнате, видят друг друга.
Если не работает: Для теста двух устройств нужен либо Editor + шлем, либо два телефона/ПК. Без App ID игра не подключится — сначала создай его.
